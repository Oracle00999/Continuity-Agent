# Documents and evidence slice

Open `/documents` from the sidebar. **Load demo runbooks** saves the six fictional Northstar sources and selects Database Backup & Restore. Repeated calls preserve the original records. Upload accepts PDF, Markdown, and UTF-8 plain text.

The normal UI and Analyst replies use names, human-readable extraction status, natural dates, and named source links. Internal IDs, text offsets, MIME types, file sizes, and passage counts are retained for processing and diagnostics but are not shown by default. Standalone Markdown headings are omitted from the normal evidence view, while their saved citation targets remain accessible.

Default runbook reviews use three brief sections—Responsibilities, Main gaps, and Still to test—with five short bullets total. Detailed audits require an explicit request. Quotes must be contiguous source excerpts; summaries cannot be labelled exact quotes. Suggestions must never be described as saved or recorded follow-ups unless a successful write actually persisted them.

Infrastructure execution requests receive a short explanation that an engineer must run the test. Continuity does not provision databases, restore backups, contact approvers, or execute smoke tests, even if access is offered. It must not replace missing execution capabilities with unsolicited runnable scripts or requests for connection strings, credentials, or signed URLs. Human verification recording remains a future slice.

## Implemented

- A shared `ingest-document` action resolves a scoped AttachmentRef, extracts text, and saves the document and its evidence in one SQL transaction.
- `list-documents` and `get-document` serve both the React screen and Continuity Analyst. Lists omit document bodies; detail reads return the exact text and passage locations.
- Source passages retain exact quotes, section labels, PDF page numbers, and zero-based UTF-16 offsets into the saved extracted text. Whitespace normalization happens before passages are constructed. Every quote is a direct slice, never an AI paraphrase.
- Exact, case-insensitive matches link passage mentions to existing workspace people/systems. This does not create entities or assert ownership, confidence, or procedure readiness.
- The six stable demo sources deliberately omit the backup location, leave rollback instructions incomplete, disagree on the infrastructure owner, and record no successful independent restoration. The defects are authored fixtures, not generated by a model.
- Documents display extraction warnings and `Text extracted` or `Needs readable text`. Neither state means a procedure is ready.
- Selected document IDs are visible through URL/navigation state and `view-screen`. The Analyst reads the source before citing it and links to a specific saved evidence passage.
- The Analyst's prompt now explicitly limits suggestions to implemented capabilities. It must not offer saved risk findings, handover plans/tasks, ownership transfers, or verification runs yet.

## File handling

`/api/document-upload` is a multipart transport only. It authenticates the caller, checks same-origin requests and workspace access, limits request bytes, and mints the framework's private AttachmentRef. Extraction and SQL writes remain in the shared action/domain layer.

Local development registers a purpose-scoped private blob provider at `data/document-blobs`. It is enabled only for a PGlite database outside production; files use opaque UUIDs, restricted permissions, and sealed owner/org AttachmentRefs. Bytes are never stored in SQL. Local files are not encrypted at rest; the opaque reference itself is sealed by Core. Hosted/production environments require configured private file storage and stable encryption material; there is no filesystem fallback there.

The installed H3/Srvx version's size-limited request loses multipart headers when calling `formData()`. The route keeps the bounded byte reader and parses a Response with the original multipart Content-Type instead. Framework packages are unmodified.

PDF text extraction uses `unpdf` 2.1.0 and page-preserving output. Limits: 5 MiB originals, 100 PDF pages, 200,000 extracted characters, and 1,000 passages. Image-only/empty pages produce warnings; OCR, image interpretation, table reconstruction, and password-protected PDFs are not supported. Rejected processing attempts do not create partial document/evidence rows. Staged files from rejected or duplicate uploads may remain in blob storage; retention cleanup is not implemented yet.

## Verified

`node scripts/smoke-documents.mjs` tests the running local app through its real authenticated HTTP endpoints. It checks all six demo sources, repeat-safe seeding, every quote's offsets, named mentions, Markdown/Unicode/line-ending handling, duplicate content, a two-page PDF, an empty PDF, type/size rejection, authentication, and invalid IDs/AttachmentRefs. It creates clearly named QA upload fixtures in the local demo workspace.

`node scripts/verify-documents-analyst.mjs` performs one live read-only OpenAI review through the same chat endpoint used by the app. Before sending anything, it asserts that the selected document is an unchanged developer-authored demo fixture. It then verifies a successful `get-document` tool event, real evidence IDs, an exact source quote, source links, and no mutating tool calls. This passed for Database Backup & Restore: the Analyst identified the unspecified backup location and lack of a recorded independent test.

Browser automation is still unavailable because the Browser skill fails during bootstrap (`Cannot redefine property: process`). The Documents route serves successfully; visual/interaction verification remains a manual check. TypeScript and Agent-Native Doctor are the required static checks.
